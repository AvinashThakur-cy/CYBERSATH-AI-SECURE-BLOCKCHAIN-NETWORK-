# CYBERSATHI | Blockchain Security Observatory

CYBERSATHI is a blockchain security operations dashboard with a FastAPI backend, validated demo workflows, explainable sample telemetry, a responsive interface, and exportable security reports.

**Important:** Dashboard metrics and incidents are illustrative sample data. The app does not connect to a blockchain, verify live wallet or email reputation, or guarantee that a URL or password is safe. Local analysis uses deterministic heuristics; treat its scores as indicators, not proof.

## Run locally on Windows

1. Create and activate a virtual environment (the included `.venv` can be used):
   `py -m venv .venv` and `.venv\Scripts\activate`
2. Install dependencies:
   `pip install -r requirements.txt`
3. Start the app by double-clicking `start.bat`, or run:
   `uvicorn app.main:app --reload --host 127.0.0.1 --port 8000`
4. Open http://127.0.0.1:8000/ (the API is intentionally local and makes no external network calls).

## Deploy a public demo with Railway

1. Sign in to [Railway](https://railway.com/new) and create a project from the public GitHub repository `AvinashThakur-cy/CYBERSATH-AI-SECURE-BLOCKCHAIN-NETWORK-`, using the `main` branch.
2. Railway installs the Python dependencies from `requirements.txt` and starts the web service using the root `Procfile`.
3. In the service settings, set the health check path to `/api/health`.
4. Under **Networking → Public Networking**, choose **Generate Domain**. Share the generated `https://<your-service>.up.railway.app/` URL.

The public domain is generated by Railway after deployment; it cannot be reserved in advance. This is an illustrative demo and does not connect to a live blockchain.

## Product capabilities

- Clearly labeled illustrative dashboard metrics for blockchain health, nodes, wallets, incidents, and sample confidence values.
- Module views for threat intelligence, attack investigation, blockchain exploration, node management, wallet intelligence, incident response, Attack DNA, and AI Copilot.
- Validated demo actions for snapshot review, wallet isolation preparation, node freeze preparation, incident escalation, and report generation. These actions do not operate on a live chain.
- JSON security report export with findings and recommended controls.
- Responsive desktop and mobile layout with command palette and light/dark themes.
- Local heuristic URL, email, and password checks; these are not reputation lookups or a guarantee of safety.

## API surface

- `GET /api/dashboard` returns the primary dashboard data.
- `GET /api/modules/{module_id}` returns module-specific evidence and actions.
- `POST /api/actions` accepts a validated action payload such as `{"action":"run-scan"}`.
- `GET /api/report` returns the exportable security report.
- `GET /api/telemetry` remains available as a compatibility payload.
- `GET /api/health` reports local service health.
- `POST /api/analyze/url` accepts `{"url":"https://example.com"}`.
- `POST /api/analyze/email` accepts `{"email":"name@example.com"}`.
- `POST /api/analyze/password` accepts `{"password":"..."}`; the password is never returned or written to audit logs.

All analysis responses use the same format: `status`, `analysis_type`, `risk_level`, `score`, `summary`, `findings`, `recommendations`, `metadata`, and `analyzed_at`. Analysis audit entries contain metadata only.
